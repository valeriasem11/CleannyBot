# Cleanny

Телеграм-бот, который автоматически удаляет сообщения от других ботов
в группе через заданное время (по умолчанию — 5 минут).

## Структура проекта

```
cleanny-bot/
├── bot.py             # точка входа
├── config.py          # чтение настроек из .env
├── handlers.py        # ловит сообщения от ботов, ставит задачу на удаление
├── jobs.py            # сама функция удаления сообщения
├── requirements.txt   # зависимости
├── .env.example       # пример настроек
└── README.md
```

## Как это работает

1. Cleanny слушает все сообщения в группе.
2. Если сообщение написано ботом (`from_user.is_bot == True`), Cleanny
   не удаляет его сразу, а планирует удаление через `DELETE_DELAY_SECONDS`
   секунд (по умолчанию 300 = 5 минут) с помощью APScheduler.
3. Запланированные задачи хранятся в SQLite (`jobs.sqlite`), поэтому если
   бот перезапустится, ничего не потеряется.
4. Через 5 минут вызывается `deleteMessage` — сообщение исчезает.

## Шаг 1. Создать бота

1. В Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot`,
   следуйте инструкциям, получите токен вида `123456789:AA...`.
2. Обязательно отключите Privacy Mode, иначе бот будет видеть в группе
   только сообщения, адресованные ему самому:
   ```
   /setprivacy → выберите бота → Disable
   ```

## Шаг 2. Добавить бота в группу

1. Добавьте Cleanny в нужную группу.
2. Назначьте его администратором с правом **«Удаление сообщений»**
   (`Delete messages`). Без этого права бот не сможет удалять чужие
   сообщения — только свои.

## Шаг 3. Установить зависимости

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Шаг 4. Настроить .env

```bash
cp .env.example .env
```

Откройте `.env` и вставьте свой токен:

```
BOT_TOKEN=123456789:AAExampleTokenReplaceMe
DELETE_DELAY_SECONDS=300
WHITELIST_BOT_IDS=
JOBS_DB_PATH=jobs.sqlite
```

`WHITELIST_BOT_IDS` — необязательный список ID ботов через запятую,
которых Cleanny не должен трогать (например, других полезных ботов
в чате).

`OWNER_USER_ID` — ваш личный Telegram ID. Только этот пользователь
может вызывать команду `/chats` в личных сообщениях с ботом. По
умолчанию уже стоит `828533150` — при необходимости замените на свой.

## Шаг 5. Запустить

```bash
python bot.py
```

В логе должно появиться:

```
Cleanny запущен как @your_bot_username
```

## Команды бота

- `/start` — приветствие и краткая инструкция
- `/help` — список команд
- `/status` — текущие настройки в этом чате (задержка удаления, вайтлист)
- `/setdelay <время>` — изменить задержку удаления **в конкретной группе**
  (доступно только администраторам этой группы)
- `/whitelist add|remove|list` — управлять списком ботов, которых не нужно
  чистить, **прямо в чате** (доступно только администраторам этой группы)
- `/pause <время>` — временно приостановить удаление в конкретном чате
  (доступно только администраторам этой группы)
- `/resume` — досрочно снять паузу
- `/chats` — **личная команда**, доступна только владельцу (ID задаётся
  через `OWNER_USER_ID`), работает только в личных сообщениях с ботом.
  Показывает список всех чатов, где бот когда-либо был, и его текущий
  статус в каждом (`member`, `administrator`, `left`, `kicked` и т.п.)

Примеры `/setdelay`:
```
/setdelay 2      → 2 минуты
/setdelay 30s    → 30 секунд
/setdelay 1h     → 1 час
```

Примеры `/whitelist`:
```
/whitelist add @CoupleStoryBot     → добавить бота по юзернейму
/whitelist add                     → (в ответ на сообщение бота) добавить его без юзернейма
/whitelist remove @CoupleStoryBot  → убрать бота из вайтлиста
/whitelist list                    → показать текущий список
```

Примеры `/pause`:
```
/pause 10   → приостановить удаление на 10 минут
/pause 30s  → приостановить на 30 секунд
/pause 1h   → приостановить на 1 час
/resume     → снять паузу раньше срока
```
Пока действует пауза, Cleanny просто не планирует удаление новых
сообщений от ботов в этом чате — все остальные функции (команды,
работа в других чатах) продолжают работать как обычно.

Настройка сохраняется в SQLite (та же база, где и очередь удалений) и
действует только для того чата, где её задали — в разных группах может
быть разное время. Если задержку не настраивали, используется значение
`DELETE_DELAY_SECONDS` из `.env` (по умолчанию 300 сек).

Минимум — 5 секунд, максимум — 48 часов (это ограничение самого Telegram:
он не позволяет боту удалять сообщения старше 48 часов).

## Постоянное хранилище (важно для bothost и подобных платформ)

Все настройки (задержка, вайтлист, пауза, список чатов) и очередь
отложенных удалений хранятся в базе данных — по умолчанию это локальный
файл SQLite, но **на облачных платформах он не переживает передеплой**,
если не подключить постоянное хранилище.

Самый надёжный вариант — использовать managed PostgreSQL (если он есть
на вашем хостинге, как на bothost):

1. В панели хостинга создайте/найдите connection string вашей PostgreSQL
   базы (обычно выглядит как `postgresql://user:password@host:port/dbname`).
2. Пропишите его в переменных окружения бота как `DATABASE_URL`.
3. Всё — бот сам создаст нужные таблицы при первом запуске и будет
   использовать эту базу вместо локального файла. Никакой Volume
   подключать не нужно.

Если `DATABASE_URL` не задан — бот тихо откатывается на локальный
SQLite-файл (`jobs.sqlite`), что удобно для разработки на своём
компьютере, но не годится для облачного хостинга без Volume.

## Ограничения Telegram API, о которых стоит помнить

- Удалить можно только сообщение, отправленное **менее 48 часов назад** —
  для задержки в 5 минут это не проблема, но если вы захотите увеличить
  `DELETE_DELAY_SECONDS` до нескольких дней, учитывайте этот лимит.
- Бот должен быть админом с правом `can_delete_messages`, иначе он не
  сможет удалять чужие сообщения.
- Без отключённого Privacy Mode бот вообще не увидит сообщения других
  ботов в группе.

## Как запустить бота на постоянную работу (24/7)

Простой `python bot.py` в терминале работает только пока терминал открыт.
Для реальной эксплуатации выберите один из вариантов ниже.

### Вариант A: systemd (Linux VPS, рекомендуется)

1. Загрузите проект на сервер, установите зависимости и `.env` как описано
   выше (шаги 3-4), например в `/opt/cleanny-bot`.
2. Отредактируйте `cleanny.service`: укажите правильные `User` и пути
   `WorkingDirectory` / `ExecStart`.
3. Установите и запустите сервис:
   ```bash
   sudo cp cleanny.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable cleanny   # автозапуск при перезагрузке сервера
   sudo systemctl start cleanny
   ```
4. Проверка:
   ```bash
   sudo systemctl status cleanny     # статус
   journalctl -u cleanny -f          # логи в реальном времени
   sudo systemctl restart cleanny    # перезапуск после изменений в коде
   ```

### Вариант B: Docker

1. Установите Docker и Docker Compose на сервере.
2. Настройте `.env` (шаг 4 выше) — `docker-compose.yml` подхватит его
   автоматически.
3. Запуск:
   ```bash
   docker compose up -d --build
   ```
4. Проверка:
   ```bash
   docker compose logs -f      # логи
   docker compose ps           # статус
   docker compose restart      # перезапуск после изменений в коде
   ```
   Файл `jobs.sqlite` сохраняется в папке `./data` на хосте, поэтому при
   пересоздании контейнера очередь удалений не теряется.

### Где взять сервер

Подойдёт любой недорогой VPS (Timeweb, Selectel, Hetzner, DigitalOcean и
т.п.) — боту достаточно минимальных характеристик (1 vCPU, 512 МБ–1 ГБ
RAM). Бесплатные варианты вроде PythonAnywhere тоже подходят для теста,
но обычно не держат постоянно работающий процесс на бесплатном тарифе.

## Возможные доработки

- Команда `/status` — показывать, сколько сообщений в очереди на удаление.
- Команда `/whitelist add <id>` — управлять вайтлистом прямо из чата,
  без правки `.env`.
- Отдельная задержка для разных чатов (сейчас она глобальная).
- Логирование удалённых сообщений в отдельный служебный чат для аудита.
